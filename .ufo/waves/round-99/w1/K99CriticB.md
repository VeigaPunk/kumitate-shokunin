## F1 — real move, but prospective (confirmed)

- 21 fleet lanes, **5,505 `## Registry` rows, 60,746 table cells → 0 cells** whose ECMAScript trim differs from
  `[ \t]` (`exposure.json`; command in `receipts.txt`).
- kumitate history: **359 commits** touching `corpus/SOURCES.md`, **46,893 Registry rows → 0** such cells.
- BASE vs reference-rule `--json` on all 21 lanes: **21/21 byte-identical**, same verdicts/findings/rows
  (`lane-json-manifest.txt`). READY candidate vs BASE: also 21/21 identical (verified in seat scratch; candidate
  fixture spot checks byte-identical to the reference rule).

So **no current or historical finding changes**. The value is preventive: it removes a latent decoder divergence
between the gate and the census for pads the gate silently accepts today (on the battery, 40 id rows, 7 duplicate
rows, 6 malformed rows and 27 rows per enum code). That is a real correctness property of a gate, but the claim is
an insurance policy, not an incident fix — as plan limit (1) already says.

## F2 — "census parity" is per-code, not one class

`scripts/sources-census.sh` has at least two cell/section classes and they can disagree on one file:

| reader | class | locale dependence (measured, `bash-trimcell-classes.txt`) |
|---|---|---|
| `row_pass` (E02, E05–E09, E12, `rows`) | `[ \t]` gawk | none |
| `usedby_findings` (E11), heading trim | bash `trim_cell` `[[:space:]]` | C.UTF-8/en_US.UTF-8: strips EMSP, VT, FF, CR, TAB, SP; **not** NBSP. C: strips only ASCII whitespace |

Measured contradictions (`extra-fixtures.json`, `sweep.json`):

- Heading `## \u2003Registry`: census emits **E12 "row outside Registry"** and **E11 "missing used-by"** for the
  same row — `row_pass` says outside, `usedby_findings` says inside; sources-check (BASE and R99) agrees with
  `row_pass`. This is pre-existing and untouched by R99.
- The same used-by file yields E11 for **20/44** pad classes under `LC_ALL=C.UTF-8` and **35/44** under `LC_ALL=C`.

Verdict on direction: aligning the **row cells** with `row_pass` is the right target — it is the reader that emits
the codes C1 cites, and it is deterministic. But the claim's scope ("every helper that calls it") also moves
`splitUsedBy`'s path parts onto a **third** class that agrees with neither reader; see D3. So C1's rationale is
sound for E02/E05–E09/E12 and `counts.rows`, and unsound as a general parity statement.

## Impacted axes and smallest safe correction

- Operability: the move is a latent-decoder correctness fix (preventive; no live exposure). Coverage sub-axes,
  finding kinds, contract id and exit map are untouched (diff scope: trim line + comments + selftest).
- **Fixable defect (route, judge must amend or accept explicitly)**: D3's 5 classes where R99 is stricter than
  BASE *and* both census locales for a used-by path that exists modulo VT/FF/CR. Smallest correction: leave
  `splitUsedBy` (path parts) on `String.prototype.trim` and evaluate `MINED_UNUSED` on the JS-trimmed cell, so
  used-by keeps BASE's behaviour while row cells take the blank class. The frozen counter cannot adjudicate this
  (`ctl-splitjs` is HELD by design), so it is a plan/rule decision, not a seat-level mutation.
- **Tradeoff the judge should reject**: D1's `ROW_FIELD_EMPTY` loss on pad-only text cells. It is inherent to
  "one helper for every cell", it moves *toward* the census (which has no empty-cell rule), and it needs no
  implementation change. If the lane wants the hygiene check, the counter-blind alternative is to evaluate
  emptiness on the JS-trimmed value — a different rule, also a judge decision.
- **Disclosure obligation** (not harm): plan limits do not mention D1 or the USED_BY_ASYMMETRY consequence; the
  candidate's in-code comment is good, but the round's knowledge/lesson should state that the class is `row_pass`
  `[ \t]` and that census E11 is a different, locale-dependent reader.

  `3052ea1b61c1334b` / `1172cfb57babd0d3`); my counter runs were the two replays above. READY candidate
