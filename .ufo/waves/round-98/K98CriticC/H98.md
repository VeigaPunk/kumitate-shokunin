## Method (no hand-invented oracle)

* **Harness extraction** (`harness/extract.mjs`, rule recorded in the file header): the byte slice
  from `const SOURCES_ROW_RE = ` through the brace-matched end of `function declaredPins(`,
  verbatim; the slice must contain exactly the four `SOURCES_*_RE` consts and one function.
  `harness/run-harness.mjs` imports the slice and reports `{declared pins, outsideRows, malformedRows}`.
* **Harness == full gate** (`harness/equiv.py`): for 3 files — the current kumitate registry, a
  synthetic file with outside + 12-field + non-ASCII-pad rows, and the 32-class pad matrix — a
  throwaway git fixture repo (`corpus/SOURCES.md`), a git main-repo fixture and a
  `round-5/kumitate.md` citing **every** pin the harness found plus a decoy 40-hex token were
  built; the tool's `--json` `citations.declared` / `outsideRows` / `malformedRows` equalled the
  harness on all 3/3 files (`receipts/equiv.json`, `receipts/equiv-candidate-inprogress.json`).
* **Expected values from the census** (`harness/compare.py`): per file
  `/home/vgpnk/Projects/shokunin/scripts/sources-census.sh validate --file <f> --today 2026-11-07`
  is executed live; OUT = E12 ids in output order; MALF = E01 ids matching `^S[0-9]{3,}$` in
  output order; DECL = the 40-hex pins of rows the census reads as Registry rows (inside
  `## Registry`, not `separator_row()`, NF==13, id `^S[0-9]{3,}$`, status cell not `rejected`
  under the candidate's unchanged status rule, carrying a 40-hex URL path segment), with the
  census `row_pass()` heading/`[ \t]`-trim/separator/NF rules re-implemented line-for-line and the
  candidate's unchanged `SOURCES_URL_RE`/`SOURCES_PIN_RE`/`SOURCES_SEGMENT_RE` pin extraction.
  Census exit ∈ {0,1} was required; nothing else occurred.
* **Attribution cross-check**: on all **400/400** compared files the re-implemented admission
  reproduces the live census's E12 list and its E01 valid-id list **exactly**
  (`census_impl_decl_mismatch: 0`; receipts in `receipts/census-receipts-all.tsv`, E01/E02/E12/ok
  lines for every run, `# <file> sha256=<sha>` headers).
* **Parser defect found and fixed (recorded)**: a census E01 id can itself contain a TAB — a cell
  ending `\t\f` defeats the `[ \t]` trim, so the TSV value is `S9143\t\f`, not `S9143`. A naive
  `split('\t')` made that look like a valid `S9143` and produced one false MALF disagreement on the
  pad matrix. `harness/compare.py` now splits `('\t', 2)` and takes the id before the last
  ` fields=`; `harness/reparse.py` re-scores saved runs from the saved census receipts without
  re-running the census. Post-fix: 400/400 census-vs-implementation agreement.
