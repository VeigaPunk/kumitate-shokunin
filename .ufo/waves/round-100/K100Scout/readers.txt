Scope: every code path under `/home/vgpnk/Projects/shokunin/*-shokunin/scripts/`
that reads a `corpus/SOURCES.md` row id and decides something from it.
Report-only: no sibling lane was edited.

The census row gate (scripts/sources-census.sh, row_pass, gawk RS=LF):
  row gate  : `^ {0,3}\|`   (0-3 ASCII SP then a pipe)
  id cell   : field 2, trimmed of ASCII SP/TAB only (POSIX blank)
  id form   : `^S[0-9]{3,}$`
  records   : one LF-delimited record is one line (gawk RS=LF)

Verdict key:
  CONFORMANT -- the reader recognises a row id exactly as the census does
  DIVERGES   -- the reader recognises a row id the census does not read as valid
  STRICTER   -- the reader reads a strict subset of the census rows (no false ids)
  N/A        -- an id-token or id-form class, not a SOURCES row reader

   row gate `^ {0,3}\|` matches the census exactly; only the id-cell pad differs (census trims ASCII SP/TAB only). The `m`-flag record break does not apply here.

2. `kumitate-shokunin/scripts/source-capture.mjs:157` — DIVERGES (id-cell pad is JS \s AND `^\s*` indent is JS \s AND the `m` flag lets `^` match after CR/U+2028/U+2029)
   three independent divergences: (a) id-cell pad; (b) `^\s*` accepts any JS white-space indent (TAB, NBSP, 4+ SP) where the census gate is `^ {0,3}\|`; (c) `m` + JS line terminators (LF, CR, U+2028, U+2029) vs gawk RS=LF -- a row following a CR/U+2028 on the same LF record is a row for this reader and not for the census.

3. `kumitate-shokunin/scripts/round-gate.mjs:411` — CONFORMANT
   row gate `^ {0,3}\|` and id-cell pad `[ \t]*` are exactly the census shape; the file comment at line 410 says so explicitly. Reads only rows in `## Registry` (inReg tracked the census way) and requires exactly 13 split fields (NF==13).

4. `kumitate-shokunin/scripts/sources-check.mjs:237` — CONFORMANT for the id cell; STRICTER for the row gate
   the id cell is trimmed of ASCII SP/TAB only -- exactly the census trim. The row gate differs in two ways: the main reader accepts any line starting with `|` (column 0 only) after normalizeMarkdownIndent() strips 1-3 leading SP, and the E12 probe is column-0 only (no 0-3 SP indent allowed). Both are stricter than the census gate, so neither can invent an id the census rejects.

   row gate and the 13-field check match the census; the cell trim is JS `.trim()` (ECMA WhiteSpace+LineTerminator), so a non-blank pad would be trimmed here and not by the census. Same id form `^S[0-9]{3,}$`. Divergence surface is the pad only.
