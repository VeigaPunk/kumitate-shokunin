## K3 zero-spawn forger evidence and B2e analysis

The scratch zero-spawn forger preserves the v2 receipt encoding and enforces the sidecar-name check (but its selftest output is explicitly counterfeit, as noted above); it passed B1, B1c, B2c, B2e, B3c, B4d, and B6. Exact A52 final line (exit status 1; retained in `forger-probe.txt`):

```text
ATTEST52: ATTEST52_UNMET held=7/13 checks=13 rev=7fde97109d86d3655a74a3e54d07fd1929dca4c6 rule=A52 version=v1 | B1 PASS | B1c PASS | B2 MISS attest52-run-1.txt:absent;attest52-run-2.txt:absent;attest52-run-3.txt:absent | B2c PASS | B2e PASS | B3 MISS attest52-run-2-replayed.txt absent | B3c PASS | B4 MISS tool or receipts dir absent | B4c MISS twinValid=true ledger(orig)=RECEIPT: TAMPERED ledger(twin)=RECEIPT: VALID | B4d PASS | B5 MISS pin 44919763!=1e3f52ca;proxy exit=1 PROXY: DRIFT (C2_TOTAL_DRIFT term=C2_total d | B5c MISS mutantReceipt=absent-or-malformed selfGuard=present | B6 PASS
```

B2c does not require predicting the probe nonce before invocation: the nonce is supplied in `argv`, and the probe's expected `printf %s` output is exactly that argument. The forger can synthesize its argv and stdout hash without executing `printf`.

B2e is also satisfiable without executing the requested child. Frozen probe lines 239–252 call the tool with `--stdin -- /bin/cat`, then read the generated nonce and independently run `/bin/cat` with `Buffer.from(j.nonce, 'utf8')`; the probe hashes this second cat's stdout. It does not capture or compare the stdout from the cat launched by the instrument. A forger can choose its nonce during receipt generation, set `stdin_sha256 = SHA256(UTF8(nonce))`, and set `stdout_sha256` to that same known byte sequence's hash. The probe's independent cat produces the same deterministic bytes. The passing B2e above is direct evidence: no child process is invoked by the scratch instrument. The nonce need not be predicted in advance; it is generated by the forger and then bound into its own record.

## Finding / risk

The forger's B4c miss exposes an apparent conflict between the frozen challenge and the v2 `SHAPE` rule. A52 lines 368–372 copies the original receipt to `orig.txt` and copies its `.sha256` sidecar bytes unchanged to `orig.txt.sha256`; that sidecar still records the original receipt basename. The v2 contract requires the recorded sidecar name to equal the receipt basename. The scratch verifier correctly treats the renamed `orig.txt` pair as TAMPERED before the ledger can report REPLAY, yielding `B4c MISS ... ledger(orig)=RECEIPT: TAMPERED`. Passing that arm by ignoring sidecar-name binding would weaken the stated v2 contract, so this strict-sidecar attempt leaves it failing. The freeze-tree's absent round-52 receipt corpus, doctored control, counter-mutant receipt, pin update, and proxy repair also explain the reported B2/B3/B4/B5/B5c misses; this experiment intentionally does not fabricate those static integration artifacts.
