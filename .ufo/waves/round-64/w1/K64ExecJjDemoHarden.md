## Findings

K64ExecJjDemoHarden-1 — HIGH. `seat_has_git_dir` is not hermetic: `git -C <seat> rev-parse --git-dir` walks *above* the mktemp fixture and finds any `.git` in the caller's TMPDIR ancestry, so the key flips. Attacks J6 (entry's stated key vs live run) for any counter/caller whose TMPDIR is inside a git worktree. Repro:
`for t in /tmp /home/vgpnk/Projects/shokunin/kumitate-shokunin/.scratch; do TMPDIR=$t bash scripts/jj-seat-demo.sh | grep seat_has_git_dir; done` → `no` then `yes`. Fixed in v2 by `export GIT_CEILING_DIRECTORIES="${S%/*}"` (same three TMPDIRs → `no`,`no`,`no`).
K64ExecJjDemoHarden-2 — HIGH. An inherited `GIT_DIR`/`GIT_WORK_TREE` makes the demo unusable and leaves residue outside the fixture. Attacks operability: a seat shell that exports `GIT_DIR` (common with `git --git-dir`/worktree scripts) gets exit 2 for the *wrong* reason plus a created `/tmp/bogus-gitdir`. Repro: `GIT_DIR=/tmp/bogus-gitdir bash scripts/jj-seat-demo.sh; echo $?; ls -d /tmp/bogus-gitdir` → `FAIL-CLOSED fixture-root`, stderr `fatal: this operation must be run in a work tree`, `2`, dir exists. Fixed in v2 by `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE GIT_OBJECT_DIRECTORY GIT_ALTERNATE_OBJECT_DIRECTORIES GIT_COMMON_DIR`.
K64ExecJjDemoHarden-3 — MEDIUM. Only 3 of ~10 mutating steps are checked; a failed `describe`/`new`/`abandon`/`workspace update-stale`/`workspace forget` would print a wrong value and still exit 0, so the demo could "succeed" with false evidence. v2 checks each and fails closed with its own reason (`jj-describe`, `jj-new`, `jj-abandon`, `workspace-update-stale`, `workspace-forget`, `cross-rewrite`, `cross-abandon`, `workspace-add-2/3/4`, `seat-change-id`, `jj-status`, `fixture-write`, `jj-log`).
K64ExecJjDemoHarden-4 — MEDIUM. Residue leak: the trap is installed only after *both* mktemp calls, so a failing second `mktemp` leaves the first fixture (E6: `tmp.uC1Qf77EqD`); and it is an `EXIT`-only trap. v2 registers `D` immediately, empties `S` safely, and adds HUP/INT/TERM traps.

The amendment's sentence "the seat's file survives on disk" must be qualified by the new key `update_stale_abandoned_seat_file=deleted-no-recovery-commit`.
K64ExecJjDemoHarden-7 — INFO, measured answer to (b). Mutual rewrite leaves both seats fresh; mutual abandon leaves both fresh after one `jj status` each **only when the other seat's working copy is empty** (jj moves it to a fresh empty commit). With content on both sides the abandoned seat is stale and cannot run a command at all, so the second abandon never happens and one `jj status` each leaves one seat stale (`A=fresh B=stale`) — staleness, not the peer, is what stops the second attacker. ## Limits

- The frozen counter `jj64-probe.mjs` was not run (its J6 needs a committed entry; no entry exists yet). Instead its parser shape was checked against v2's output: 18 keys all matching `^JJ_SEAT: ([a-z0-9_]+)=(.*)$`, no duplicates, no empty values, DONE line matching `^JJ_SEAT_DEMO: DONE jj=\S+$`.
- Signal cleanup is *not* proven: HUP/INT/TERM were sent at 0.15 s with both fixtures present, but bash completed the run anyway (`wait-exit=0`, no residue) in all four cases, so the added traps are defensive and unverified. The mktemp-failure leak (F4) *is* proven.
- Determinism and every value are host-bound: jj 0.45.1 / git 2.56.0. A different jj may change (a)/(b) semantics (update-stale message, auto-move of an abandoned seat) — the v2 keys would then read differently, not silently pass.
- The `LC_ALL=C` and `unset GIT_*` additions were checked to be output-neutral here; a caller with a hostile global git config (hooks, `core.fsmonitor`) was not exercised — the demo never commits.
- Not attacked: jj's own concurrency (`jj op log` races between two simultaneous `workspace add`s), and `update-stale` on a head abandoned *by another workspace while the seat has content* was measured only through the stale path, not through a concurrent race.
