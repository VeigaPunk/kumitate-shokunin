VERDICT: jj-seat-demo.sh is functionally correct on this host (jj 0.45.1; all 15 keys reproduce byte-identically, exit 0) but is not hermetic against ambient env vars, derives two keys vacuously, and mis-attributes the stale/fresh asymmetry to op-kind when the real rule is working-copy tree-identity — a tree-changing rewrite stales the seat too.

## Evidence

Host: `jj 0.45.1-7c41cdeb…`, `git 2.56.0`, ambient `~/.config/jj/config.toml` present (`user.name=CritC3`, `ui.default-command`, `git.auto-local-bookmark`) and **suppressed** by `JJ_CONFIG=/dev/null`.

- Rewrite: `describe -r <seat@>` changed commit `070b33d8→e6baaa69` (same change id `vqqzqwsoxztm`); `jj -R D --ignore-working-copy workspace list` immediately after shows `seat1 … e6baaa69` — the seat wc record was **auto-repointed**, never observed stale. Real rewrite, confirmed via commit-id change.
- Abandon: `abandon <seat@>` prints `Abandoned 1 commits`; seat `--ignore-working-copy log -r @` shows **new change id** `ywpkllxlwmwt→wklxokprslnx` (empty sibling, no successor); `jj -R SEAT status` → stdout empty, stderr `Error: The working copy is stale (not updated since operation …)`. `update-stale` output: `removed 1 files` (deletes `seat.txt` — `kept` is only the stale-moment state).
- Tree-identity rule (decisive): `squash --from @ --into <seat@>` (file moved into seat's commit) → seat `status` = `Error: The working copy is stale` — a **rewrite** that stales. Abandon of `seat2` whose head is the identical empty commit → `status` = `fresh`, `update-stale` on it prints `Attempted recovery, but the working copy is not stale.` exit 0.
- Op attribution: `op log` args show the demo's count-2 = 1 seat snapshot (`args: … -R …/seat1 status`) + 1 default snapshot (from `describe -m base`). Seat-attributed delta around `jj -R SEAT status` = exactly +1.
- `--ignore-working-copy` real test: `pend.txt` pending + `st --ignore-working-copy` → op count 7→7, `pend.txt` absent from status; demo's key instead wraps `jj log` on a clean wc — guaranteed `no` regardless of the flag.
- Hermeticity: `JJ_USER=EnvLeaked JJ_CONFIG=/dev/null jj config get user.name` → `EnvLeaked` (env layer bypasses `/dev/null`; `--config` flags still win for the two keys J sets). `GIT_DIR+GIT_WORK_TREE git -C $D init` → repo created at `$E/repo.git` while `rev-parse --show-toplevel` prints `$D` (line-17 guard passes). `GIT_DIR=<real .git> git -C $SEAT rev-parse --git-dir` → exit 0 → `seat_has_git_dir` would print `yes`. `GIT_CONFIG_GLOBAL` `[init]defaultBranch=INJECTED` → `symbolic-ref HEAD` = `refs/heads/INJECTED`. `jj git init` itself ignores `GIT_DIR`/`GIT_WORK_TREE` (writes cwd) and does not read any parent repo config — it only fails if run inside an existing jj repo (fixture is safe: fresh mktemp; `jj git init` inside an enclosing jj repo *succeeds*, tested).
- Answers to posed questions: (a) every J call after init names `-R`; init relies on `(cd "$D")`, safe under mktemp; no call can reach the lane. (b) `JJ_CONFIG=/dev/null` suppresses ALL file config (XDG, `~/.jjconfig.toml`, `[aliases]` — verified) but not `JJ_*` env vars. (c) grep keys match verbatim wording `The working copy has no changes.`/`Error: The working copy is stale` on 0.45.1 (locale-inert — jj is not localized; wording is version-pinned effectively). (d) `abandon` with no seat file → `fresh` + `files_on_disk` key would print `removed` though nothing existed. (e) `absolute_path_write_seen_in_default` proves only snapshot-of-tree-file; write originates from the demo process, "absolute path" varies nothing.

## Findings

- **K64ReviewDemo-1** (medium, hermeticity): ambient git env can break the "every repository is a fresh mktemp fixture" contract. Repro: `E=$(mktemp -d); GIT_DIR="$E/r.git" GIT_WORK_TREE="$D" git -C "$D" init -q` → repo lands in `$E`, line-17 guard still passes; `GIT_DIR=<real> git -C "$SEAT" rev-parse --git-dir` flips `seat_has_git_dir` to `yes`. Fix: `unset GIT_DIR GIT_WORK_TREE GIT_CONFIG_GLOBAL GIT_CONFIG_SYSTEM GIT_CONFIG_NOSYSTEM GIT_CONFIG_COUNT GIT_INDEX_FILE GIT_AUTHOR_NAME GIT_AUTHOR_EMAIL GIT_COMMITTER_NAME GIT_COMMITTER_EMAIL`; add guard `[ -d "$D/.git" ]`.
- **K64ReviewDemo-2** (medium, honesty): the stale/fresh keys conflate op-kind with the real rule — auto-repoint iff the repointed wc commit's tree equals the on-disk state. `squash --into` (a rewrite) stales; empty `abandon` doesn't. Keys as named ("rewrite_seat_head…"/"abandon_seat_head…") invite the wrong induction; plan's staged claim "the seat does not go stale" holds only for tree-preserving ops. Repro in Evidence. Fix: rename/explain keys + add controls `rewrite_treechange_seat_state=stale`, `abandon_empty_seat_state=fresh` (in v2 draft).
- **K64ReviewDemo-3** (medium, honesty): `ignore_working_copy_adds_op` (line 37-40) is unfalsifiable — flag wraps read-only `jj log` on a clean wc, so `n1==n2` holds even if the flag were a no-op. Fix: pend a file then run `st --ignore-working-copy`; assert op-delta 0 AND file hidden (v2: `ignore_working_copy_hides_pending=yes`).
- **K64ReviewDemo-4** (low, honesty): `seat_snapshot_in_shared_op_log=2` counts ALL `snapshot working copy` ops (1 seat + 1 incidental default `describe` snapshot); value is fixture-incident, not seat-attributed. Fix: op-count delta across a seat-side command (yields 1, deterministic) or grep op `attributes()` for the seat path.
- **K64ReviewDemo-5** (low, honesty): mutating steps are unchecked — `describe`/`abandon`/`update-stale` (lines 44,50,54) swallow failures into outcome keys (failed abandon → `fresh`+`kept`; `update-stale` on non-stale wc exits 0 → `update_stale_recovers=yes` vacuously). Fix: `|| fail` guards + assert stale precondition before `update-stale`.
- **K64ReviewDemo-6** (low, hermeticity): `JJ_CONFIG=/dev/null` blocks file config but `JJ_USER`/`JJ_EDITOR`/`JJ_SSH`/`JJ_*` env layers pass through (`JJ_USER=EnvLeaked` → `config get user.name` = `EnvLeaked`); name/email happen to be overridden by `--config`, other env keys aren't. Fix: unset `JJ_USER JJ_EMAIL JJ_EDITOR JJ_SSH …`, or run J via `env -i PATH=… HOME=…`.
- **K64ReviewDemo-7** (low, honesty): `absolute_path_write_seen_in_default` over-claims "seat can write into default" — the write is demo-process-originated and path-form is irrelevant (plain fs write + snapshot). Fix: perform write `(cd "$SEAT" && echo leak > "$D/leak.txt")` and comment that jj offers no fs containment (OS perms rule). Same class: `files_on_disk` collapses never-present/kept; grep `working copy is stale` is case-sensitive (`Error: The working copy is stale` — robust only because `2>&1` merges; use `-qi`).
