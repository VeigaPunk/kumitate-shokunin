## Findings

- **K64ReviewTool-1 (high)** — `--opt=value` tokens are invisible to `opt()` (`argv.indexOf(k)`). `--rev=<x>` silently selects worktree mode, so a report can pass by citing *uncommitted* receipts — a soundness hole: rev-mode receipt authority is bypassed while the meta line still prints `rev=worktree`, looking like intent. Also `--fleet=<dir>` is ignored (weaker but same class). Repro: item 1 above; compare `--rev deadbeef` (exit 2) vs `--rev=deadbeef` (exit 0 reading an untracked file). Minimal diff: after slicing argv, normalize `=` forms — `const flat = argv.flatMap(a => /^--\w+=/.test(a) ? [a.slice(0,a.indexOf('=')), a.slice(a.indexOf('=')+1)] : [a]);` then run `opt`/`includes('--selftest')` over `flat`; or simpler, fail usage when `argv.some(a => /^--(rev|fleet|lane|round|report)=/.test(a))` is false-handled — i.e. accept the `=` form everywhere. Cheapest fix: `const norm = argv.map(a => a.replace(/^(--(lane|round|report|rev|fleet))=/,'$1 ')).join? ` — cleanest is the flatMap above plus keep `opt` unchanged.
- **K64ReviewTool-2 (high)** — TALLY clause-2 cross-label false accept, line ~82: `l.includes(label) && /held=x\/y\b/.test(l)` accepts when the label appears anywhere on the line and `x/y` belongs to another `_HELD/_UNMET` token. Repro: item 2. Minimal diff: `const line = (l) => new RegExp(`\\b${label}[^\\n]{0,200}?held=${x}/${y}\\b`).test(l) || l.includes(`${label} held=${x}/${y}`);` where the first alternative forbids another `_HELD|_UNMET` boundary between label and value: `/\\b${label}(?![^\\n]*_[HU](?:ELD|NMET)\\b)[^\\n]{0,200}?held=${x}\/${y}\\b/` — simplest correct fix is dropping clause 2 entirely (contiguity already covers `LABEL held=x/y`); keep clause 2 only if receipts are known to interpose prose, then bound it as above.
- **K64ReviewTool-3 (medium)** — HASH40 `/\b[0-9a-f]{40}\b/` is case-sensitive and `\b`-anchored: uppercase or >40-char-prefixed dead hashes evade every hash check. Repro: item 3 (exit 0). Minimal diff: `/\b[0-9a-fA-F]{40}\b/g` and lower-case `m[0]` before use; optionally `/(?<![0-9a-fA-F])[0-9a-fA-F]{40}(?![0-9a-fA-F])/g` so a 41-char hex run still flags rather than hiding.
- **K64ReviewTool-4 (medium)** — receipt filename charset gaps: RECEIPT_PATH excludes space, `/`, and non-ASCII (false `RECEIPT_MISSING` or truncated matches, item 4/6), and `ls-tree --name-only` C-quotes names containing newline/quote → `git show rev:<quoted>` fails → file silently dropped (false `TALLY_UNRECEIPTED`, item 4). Minimal diff: use `ls-tree -r -z --name-only` and split on `'\0'` (spawnSync already gets raw stdout; add `{encoding:'buffer'}` or keep utf8 and split `'\0'`), and extend the regex to `\.ufo/waves/round-${round}/(?:base|close)/\S+` or `[A-Za-z0-9._\/-]+` if spaces must stay excluded — decide which; at minimum add `/` so nested paths match full names.
- **K64ReviewTool-5 (medium-low)** — receipt reads fail silently: `ls.status!==0 → continue`, `b.status!==0` (incl. 64 MB maxBuffer ENOBUFS on committed blobs, item 5) drops the file, producing false TALLY_UNRECEIPTED instead of FAIL-CLOSED. Never yields false CLEAN, so bounded; still, any IO error reading receipts should exit 2. Minimal diff: on non-zero status `add('RECEIPT_MISSING', f)` is wrong — instead collect errors and have `diffReport` throw/`render` emit exit-2 `FAIL-CLOSED receipt-unreadable <f>`; raise `git show` maxBuffer to `256*1024*1024` (same as `git()`).
- **K64ReviewTool-6 (medium-low)** — worktree vs rev divergence: rev mode recurses (`ls-tree -r`), worktree mode uses non-recursive `readdirSync` + EISDIR-swallowing `readFileSync` → subdir receipts unread in worktree mode (item 6, false DRIFT). Worktree mode also follows symlinks outside the lane (information read, then dropped or misused as receipt text). Minimal diff: recursive walk (`readdirSync(dir,{recursive:true})` or `fs.glob`) mirroring `ls-tree -r`, and `lstatSync(...).isFile()` guard; skip or dereference-check symlinks per policy.
- **K64ReviewTool-7 (low)** — `^{commit}` peel mislabels existing tree/blob objects as `HASH_DEAD` (item 7). A report citing a real tree hash gets a false DRIFT line. Minimal diff: check `cat-file -e h` first; if exists but not a commit, emit a distinct id (e.g. `HASH_NOT_COMMIT`) or accept silently per contract intent.
- **K64ReviewTool-8 (low)** — required-section / SHONEN checks are raw line regexes with no fence awareness: a report whose only headings live inside a code fence reads CLEAN (item 8). If the six headings are a structural contract, strip fenced blocks before section checks. Minimal diff: `const prose = text.replace(/^```[^\n]*\n[\s\S]*?(?:^```|\Z)/gm, '')` then run REQUIRED/SHONEN on `prose` (keep PLACEHOLDER/TALLY/HASH on full text).
- **K64ReviewTool-9 (low)** — `tip` fallback: `git rev-parse HEAD` failure still yields stdout `'HEAD'`, so `merge-base --is-ancestor h HEAD` runs against a nonexistent rev → every live lane hash reads `HASH_ORPHAN` on an unborn branch instead of the check being skipped or the run failing closed. Minimal diff: `const hp = git(lane,['rev-parse','HEAD']); const tip = rev || (hp.status===0 ? hp.stdout.trim() : null)`; when `tip==null` skip the ancestor check (or FAIL-CLOSED).
- **K64ReviewTool-10 (low)** — selftest leaks and crashes off the happy path: `mkdtempSync` precedes any git availability check; `spawnSync` ENOENT leaves `stdout` undefined → TypeError at line 112 (item 9), mkdtemp dirs remain in $TMPDIR (observed `/tmp/rrd-self.AK9vsh`, `rrd-self.iQcdpO`). Minimal diff: wrap the body in `try { … } finally { rmSync(T,{recursive:true,force:true}) }`, and check `g('init','-q').status===0` (or `git(D,['--version'])`) before use.
- **K64ReviewTool-11 (info)** — fleet auto-detect (`dirname(laneAbs)/.git`) makes any commit in the parent dir's repo satisfy a cited hash with no ancestor requirement (item 10; hash `603ddccd…` absent from lane → CLEAN). Documented, but a lane nested inside an unrelated repo inherits that repo as "fleet" silently. Consider requiring `--fleet` explicitly or printing the resolved fleet in the meta line.
- **K64ReviewTool-12 (info)** — no ReDoS found: all report-facing regexes are linear (`{2,}` on disjoint classes, no nested quantifiers/backrefs); a 4 000 000-line / 80 MB receipt file scanned in ~0.7 s; module-level `g` regexes are only fed to `matchAll`/`match`/`test` once each per line (lastIndex not a bug vector here; `line()`'s `new RegExp` is per-tally — compiles per receipt line, O(lines×tallies), still fast at 80 MB).
