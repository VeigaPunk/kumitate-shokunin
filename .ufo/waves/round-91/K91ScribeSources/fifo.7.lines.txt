66	fifo(7) Miscellaneous Information Manual fifo(7)
67	
68	NAME top
69	fifo - first-in first-out special file, named pipe
70	
71	DESCRIPTION top
72	A FIFO special file (a named pipe) is similar to a pipe, except
73	that it is accessed as part of the filesystem. It can be opened
74	by multiple processes for reading or writing. When processes are
75	exchanging data via the FIFO, the kernel passes all data
76	internally without writing it to the filesystem. Thus, the FIFO
77	special file has no contents on the filesystem; the filesystem
78	entry merely serves as a reference point so that processes can
79	access the pipe using a name in the filesystem.
80	
81	The kernel maintains exactly one pipe object for each FIFO special
82	file that is opened by at least one process. The FIFO must be
83	opened on both ends (reading and writing) before data can be
84	passed. Normally, opening the FIFO blocks until the other end is
85	opened also.
86	
87	A process can open a FIFO in nonblocking mode. In this case,
88	opening for read-only succeeds even if no one has opened on the
89	write side yet and opening for write-only fails with ENXIO (no
90	such device or address) unless the other end has already been
91	opened.
92	
93	Under Linux, opening a FIFO for read and write will succeed both
94	in blocking and nonblocking mode. POSIX leaves this behavior
95	undefined. This can be used to open a FIFO for writing while
96	there are no readers available. A process that uses both ends of
97	the connection in order to communicate with itself should be very
98	careful to avoid deadlocks.
99	
100	NOTES top
101	For details of the semantics of I/O on FIFOs, see pipe(7).
102	
103	When a process tries to write to a FIFO that is not opened for
104	read on the other side, the process is sent a SIGPIPE signal.
105	
106	FIFO special files can be created by mkfifo(3), and are indicated
107	by ls -l with the file type 'p'.
108	
109	SEE ALSO top
110	mkfifo(1), open(2), pipe(2), sigaction(2), signal(2),
111	socketpair(2), mkfifo(3), pipe(7)
