68	NAME top
69	/proc/pid/root/ - symbolic link to root directory
70	
71	DESCRIPTION top
72	/proc/pid/root/
73	UNIX and Linux support the idea of a per-process root of
74	the filesystem, set by the chroot(2) system call. This
75	file is a symbolic link that points to the process's root
76	directory, and behaves in the same way as exe, and fd/*.
77	
78	Note however that this file is not merely a symbolic link.
79	It provides the same view of the filesystem (including
80	namespaces and the set of per-process mounts) as the
81	process itself. An example illustrates this point. In one
82	terminal, we start a shell in new user and mount
83	namespaces, and in that shell we create some new mounts:
84	
85	$ PS1='sh1# ' unshare -Urnm;
86	sh1# mount -t tmpfs tmpfs /etc; # Mount empty tmpfs at /etc
87	sh1# mount --bind /usr /dev; # Mount /usr at /dev
88	sh1# echo $$;
89	27123
90	
91	In a second terminal window, in the initial mount
92	namespace, we look at the contents of the corresponding
93	mounts in the initial and new namespaces:
94	
95	$ PS1='sh2# ' sudo sh;
96	sh2# ls /etc | wc -l; # In initial NS
97	309
98	sh2# ls /proc/27123/root/etc | wc -l; # /etc in other NS
99	0 # The empty tmpfs dir
100	sh2# ls /dev | wc -l; # In initial NS
101	205
102	sh2# ls /proc/27123/root/dev | wc -l; # /dev in other NS
103	11 # Actually bind
104	# mounted to /usr
105	sh2# ls /usr | wc -l; # /usr in initial NS
106	11
107	
108	In a multithreaded process, the contents of the
109	/proc/pid/root symbolic link are not available if the main
110	thread has already terminated (typically by calling
111	pthread_exit(3)).
112	
113	Permission to dereference or read (readlink(2)) this
114	symbolic link is governed by a ptrace access mode
115	PTRACE_MODE_READ_FSCREDS check; see ptrace(2).
116
