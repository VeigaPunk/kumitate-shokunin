## Bearing on the installed OMP release

The host-installed release, OMP v18.12.6, still carries both deprecated MCP features this registry tracks.

**Roots.** The client declares the `roots` capability in every initialize handshake and answers `roots/list` itself. Capture S204 (`.ufo/waves/round-65/build/Capture/omp-v18.12.6-mcp-client.ts`, sha256 `479aef6ddda012f8402bc2480637a8c71ada8597d9705a56080dd3ed7c7d3fe9`, byte-identical to the live tag file fetched 2026-10-27) declares it at line 102, `roots: { listChanged: false },` inside the `capabilities` block (lines 101–103), and answers at lines 59–64: `case "roots/list": { const cwd = getProjectDir(); return { roots: [{ uri: url.pathToFileURL(cwd).href, name: path.basename(cwd) }] }; }`. The obligation is stated in the code at lines 171–173: "The initialize request declares roots capability, so we must respond to roots/list — even for short-lived test connections." Byte check of the installed binary `~/.local/bin/omp` (275,986,608 bytes, read-only): `roots/list` ×3, `roots: { listChanged: false }` ×1, `getProjectDir` ×3 — declaration and handler are compiled into the release. Against the Roots row (deprecated 2026-07-28; earliest removal "First revision released on or after 2027-07-28") the installed release is inside the announced window and must drop the capability by that revision.

**HTTP+SSE.** The client still routes `type: "sse"` servers to the legacy transport: S204 lines 81–82, `case "sse": return createSseTransport(config as MCPSseServerConfig, signal);`, importing `createSseTransport` from `./transports/sse` (line 11). That source ships in the release tree at the registry's sse.ts row, `https://raw.githubusercontent.com/can1357/oh-my-pi/v18.12.6/packages/coding-agent/src/mcp/transports/sse.ts` (15,183 bytes, sha256 `0b69229a69b01a372117d3d86833ec40e8f5118efe1049fdc4993ae1c677fbb0`), defining `LegacySseConnectionTimeoutError` (line 39) and `LegacySseTransport` (line 47), thrown at line 138. Byte check of the installed binary: `LegacySseConnectionTimeoutError` ×4 and the sourcemap path `// packages/coding-agent/src/mcp/transports/sse.ts` — the legacy transport is compiled into the release. Upstream `main` (fetched 2026-10-27) is unchanged on both points: `client.ts` is byte-identical to the S204 capture and `transports/sse.ts` still exists at the same hash, so no removal has landed upstream yet; on this evidence the HTTP+SSE clock ("Three months after SEP-2596 reaches Final") has not started. Presence in source and binary is not proof the host exercises either path at run time.
