## Findings

1. **High — K68CriticC1Thesis-1 — forced false/misleading row.** The r66 operator note is explicitly not a defect and promotion-owned, yet L3 requires a closed/wontfix row for every r66 parsed item. Smallest safe correction: distinguish informational/non-lane items in the source/parser and exempt them from closure (or add an explicit `not-applicable` status); do not silently call them answered defects.
2. **Medium — K68CriticC1Thesis-2 — answer binding is provenance, not repair.** A closed row can quote any eligible lane file line, including a LOG/lesson convention restatement; the predicate checks location/absence-at-base, not whether that line fixed the finding. Older 55–65 items need no answers at all. The existing lessons and LOG already record routed answers/corrections, so this is partly a second bookkeeping layer; its defensible added value is coverage/indexing and a mechanical quote locator, not proof of remediation. Smallest safe correction: describe/admit it as a coverage/provenance index, with closure adequacy explicitly non-author, rather than claiming answer binding changes fix behavior.
3. **High — K68CriticC1Thesis-3 — PATH defeats counter confinement.** Reproduction above returns exit 0 although the real counter never ran: inherited PATH selects the shim as `node`; PATH also selects `git`, `bash`, or `tar` for other subprocesses. This undermines L1/L4/L7 evidence. Smallest safe correction: resolve trusted executable paths before spawning (including the initial invocation boundary), or reject a non-allowlisted PATH; add a PATH-poison fixture.
4. **Low — K68CriticC1Thesis-4 — hardenings are mixed, not all theatre.** Second-section, quote length/ambiguity, exact-line answer and fence-aware counting address demonstrated v1 parser weaknesses. However, v1 already rejects normalized paths beginning `..` (`routed-ledger.mjs:213-215`), so presenting `..` as a newly discovered hardening overstates that part; only symlink-chain protection is new there. The `GIT_DIR` hardening addresses tool execution outside the counter, but the counter itself rejects GIT_DIR and gives children an allow-list (`ledger68-probe.mjs:20,46-47`). Fence-aware count matches the 61 real items, so its observed benefit here is adversarial robustness, not fixing a current count discrepancy. Smallest safe correction: separate genuinely new protections from inherited protections and state their boundary.
