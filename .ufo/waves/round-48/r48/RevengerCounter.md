## Reconstructed contract and execution flow

The probe accepts `<lane> <rev>` and optional `--set r48|r47`; absent `--set`, it selects r48 (`F48` source lines 90-108; current A48 lines 99-117). It resolves `<rev>^{commit}` with `git -C <lane> rev-parse`, then obtains the set's fixed base revision. r48 contains RG742, SP491, SP519, SP1592; r47 contains five older measurement sites (F48 lines 61-88). The set signatures are argv/path-shape checks, not source-location instrumentation.

For each measurement, `measure` creates a `git archive` of that revision, extracts independent trees, generates one random canary key/value for that measurement, and runs each gate's `--selftest`. It makes one base run per gate, validates that base, then three target runs per gate (`RUNS=3`). The three trees for one gate run concurrently; gates run sequentially (F48 lines 44-46, 313-345; current A48 lines 50-52, 326-358). Logs and trees are scratch data, removed after a normal measure completion.

`runGate` invokes `prlimit --fsize=4 GiB`, then `timeout -k 10 1200`, then `strace -f -qq -v -s 8192 --decode-pids=pidns -e trace=execve,execveat,clone,clone3,fork,vfork -e signal=none -o <log> -- <node> <tree>/scripts/<gate>.mjs --selftest` (F48 lines 200-229; current A48 around 209-242). It plants the canary in the gate environment, captures stdout/stderr, checks that a log exists and is at most 1 GiB, parses it, and extracts the gate's output summary. The one-GiB post-check is stricter than the four-GiB file-size limit. Stdout storage is capped at about 64 MiB: later chunks are counted in `outLen` but not retained (F48 lines 208-226). Stderr is retained by chunk count (first 64 chunks), not as a complete diagnostic stream.

On normal completion, each target run contributes to a per-site union of reasons. A site is held only when that union is empty; final exit is 0 iff every site in the selected set is held, otherwise 1 (F48 lines 347-378; current A48 lines 360-392). `die()` writes `CAPROUTE48: ERROR …` and immediately exits 2 (F48 line 90; current line 99). Exit 2 is not a negative score under the plan's kill rule.

## Parser state machine

The frozen parser is `parseStrings` at F48 lines 104-138 and `parseLog` at 140-197. The A48 version retains the same parser behavior.

1. **String-vector decoding.** `parseStrings` expects an opening `[` at the supplied index and walks toward `]`. It emits quoted strings only; whitespace/commas, `...`, C-style `/*…*/` comments, and non-string vector members are skipped. It decodes common escapes, two-digit hex, and up-to-three-digit octal escapes; an optional `...` following a closing quote is treated as a strace truncation marker. It does not validate that the supplied index actually points at `[`, that a closing bracket was found, or that every vector element was decoded. The successful `execve` path is decoded from the initial quoted pathname; argv and envp are found by searching for successive `[` characters.
2. **Physical line and PID.** Split the log on literal newlines. An empty line is ignored. Every other line must begin `decimal-PID + one-or-more spaces`; otherwise it dies with `unparsed trace line` (F48 148-152). The widened ` +` prefix is deliberate: it accepts strace's padded PID field after PID wrap. PID becomes the process key for pending calls and ancestry.
3. **Unfinished call.** If the body ends exactly in `<unfinished ...>`, inspect the leading syscall name. An untracked/non-syscall line is skipped. A tracked syscall is stored as `{call, body-with-suffix-removed}` under that PID and processing continues. A second pending tracked call for that PID is exit 2 (F48 153-158).
4. **Resume/join.** A body exactly matching `<... CALL resumed>TAIL` is joined to that PID's pending body. For a tracked call, there must be a pending entry with the same syscall name; otherwise exit 2. The entry is deleted and the joined record increments `resumed` (F48 160-168). This is the load-bearing fix for short resumed returns padded to a column: the resulting return regex accepts any whitespace between `)` and `=` (F48 171-175). A still-pending entry at EOF is exit 2 (193-197).
5. **Tracked complete records and return.** Only `execve`, `execveat`, `clone`, `clone3`, `fork`, and `vfork` are interpreted. A recognized traced call must end with `)`, whitespace, `=`, a signed decimal return, optionally the decoded PID-namespace comment, and optionally an errno text; anything outside that suffix shape is exit 2. Other syscall names and numeric-prefixed non-call notices are silently skipped (F48 169-175).
6. **Graph and successful execs.** Successful `execveat` (return 0) increments a global counter; its path/argv are not decoded. Failed `execve` is ignored. A successful `execve` must have a quoted path, then its path/argv/envp are recorded with a monotonically increasing sequence; the first such PID becomes `rootPid`. A successful fork/clone-family return greater than zero creates `childPID -> parentPID`; a PID already in the parent map is exit 2 (F48 176-197). Child return-zero records do not add edges. The optional `/* N in strace's PID NS */` return is preferred to the literal value so the edge uses the PID matching the trace prefix.

The parser does **not** prove that every byte/line is a syscall record: its completeness rule is strict for unprefixed nonempty lines and recognized traced calls, but numeric-PID lines whose body is a non-traced notice or another unrecognized syscall are skipped. For example, `+++ exited…+++`/`+++ killed…+++` and `restart_syscall(...)` shapes are skipped by this code; prior parser review reports those as synthetic cases, while its live `-qq` trace had no exit notices (`build/ReviewCounter48.md:104-110`). Thus the header's broad phrase “every non-empty line that does not parse” is not literal; `-qq` plus the syscall filter is relied upon to keep skipped notices from carrying relevant exec/clone evidence.

## Judge chain and site accounting

For each site, `judge` considers successful `execve` records only, excluding the root, exact machine paths (`/usr/bin/systemd-run`, `/usr/bin/env`, `/usr/bin/bwrap`, `/usr/bin/systemctl`), and records whose `argv[1]` is the tree's cap-run path. Remaining records must satisfy both the site's argv matcher and executable-kind predicate (F48 47-52, 65-75, 280-293).

For every candidate child exec `E`, it walks the recorded PID ancestry and requires an earlier successful-exec sequence in this order:

`node <this archive's scripts/cap-run.mjs> (R)` → `/usr/bin/systemd-run` with `--scope` and qualifying own properties (S) → `/usr/bin/bwrap` with `--unshare-pid`, `--clearenv`, `--die-with-parent` (B) → `E`.

The ancestry may contain intermediate PIDs; `before(pid, seq)` requires each recorded exec to precede the next link. `scopeProps` reads only systemd-run argv before `--`, supporting `-p K=V`, `--property K=V`, `--property=K=V`, and concatenated `-pK=V`; `isScope` requires exact path, `MemorySwapMax=0`, `MemoryMax=<integer>M <= 1024`, and `TasksMax=<integer> <= 256`. `isBwrap` requires the exact `/usr/bin/bwrap` path and checks flag membership. The candidate's envp is scanned for the random `CANARYKEY=` prefix. Each candidate increments `capped` iff an ordered cap-run ancestor exists and the canary is absent; missing link reasons are separately retained (`no_bwrap_ancestor`, `no_capped_scope_ancestor`, `no_cap_run_ancestor`, `canary_in_env`) (F48 231-310). This matches the frozen runner's observed construction: `capSpawnSync` launches Node with absolute `CAP_RUN` (frozen `scripts/cap-spawn.mjs:26,33-40`), and `cap-run` launches systemd-run with the resource properties, then `env -i`/bwrap and the three required flags (frozen `scripts/cap-run.mjs:177-190`).

`isBwrap` checks those three strings with `argv.includes`, not by parsing only bwrap's option segment before `--`. Thus it validates their presence in argv, not that bwrap consumed them as options; `--unshare-pid` and `--die-with-parent` have no separate semantic check. This is a source-derived false-held risk if those strings occur only in the child command's argv. The canary scan is a separate partial check for `--clearenv`, not proof that bwrap parsed that option.

The direct-child check is separate. For PIDs whose recorded parent is the gate root, it allows: exactly one Node exec of the absolute cap-run path; any sequence consisting solely of `/usr/bin/git` or `/usr/bin/mkfifo`; or the set's `allowDirect` shape. r48 `allowDirect` accepts a first exec of a nested `<gate>.mjs --selftest` Node or a `sh|bash|dash -c` direct child; r47 has no such named allowance (F48 47-48, 71-86, 263-277). It skips direct children with no successful `execve` record. The allowances inspect only a PID's collected successful exec records; the nested-selftest and shell cases are recognized from `ex[0]` only.

The base gate is one run, validated for status 0, a parsed summary with total >= 1 and pass == total, final PASS verdict, and at least one site candidate. It does not require the base itself to be unheld, and does not validate base `failLines`, execveat, or (under A48) case-line counts (F48 347-352). Each target run contributes these reasons: nonzero gate status; no candidate; candidate count unequal to base; any candidate uncapped; any disallowed direct child; any successful execveat; missing final verdict; FAIL line; summary invalid or below base. For A48 case-line gates it also adds `summary_uncorroborated` if per-case-line count != summary total or PASS-line count != summary numerator (current source lines 234-239, 349-350, 373-384). Reasons are unioned across all three target runs, so one bad run misses that site.

## Hidden assumptions and uncovered behavior

- **Record format / syscall coverage.** It assumes `strace -f` emits one PID-prefixed physical record per line, with records for exactly the selected syscall names. No timestamps or alternate `[pid N]` prefixes are enabled. `--decode-pids=pidns`'s exact comment form is required for namespace-aware child edges. A successful call with an unrecognized/non-numeric return or changed formatting fails closed; unrecognized numeric-prefixed bodies are skipped.
- **Argument/environment rendering.** `-v` must keep envp fully rendered as a string vector for canary detection; if it were abbreviated to an address/count with no `[`, `parseStrings` does not fail and envp defaults to empty. `-s 8192` bounds individual printed strings; the parser accepts truncation but does not authenticate it. The code assumes candidate path/argv signatures and canary key remain visible in that rendering. The parser is a narrow C-string-list decoder, not a validating strace grammar.
- **Thread-leader exec.** A real strace 7.2 non-leader-thread exec can produce `execve(...) <pid changed to N ...>`, a `+++ superseded…+++` notice, then a resumed record under a different PID. That first traced exec has no numeric return, so this parser exits 2 rather than scoring. This is confirmed by a live log and extracted-parser report (`r48/ReviewCounterD1.md:14-35`); that report's frozen selftest runs saw no such cluster (`:37-59`). It is an honest-fail/retry risk, not a false-held path.
- **PID identity.** Prefix PIDs and `clone*` return PIDs must be reconcilable. The parser treats a second create-return for the same child PID as exit 2 rather than modeling PID reuse. The `^([0-9]+) +` prefix and PID-namespace comment logic address the two measured R47 losses: return-column padding and PID-prefix padding/wrap. The F48 receipts report AT802 106/106 in all three parser runs where A2 lost 1–3 records (`probe/receipts/rc-at802-parser.txt:1-13`); the counter header records the PID-wrap correction (F48 21-36).
- **Output is an oracle, not suite semantics.** Even A48 counts matching prefixes, not unique case IDs, order, actual test execution, or which process emitted the lines. It sees the captured process-tree stdout as one stream. A mutation able to print synthetic case lines and a matching summary can still satisfy the textual predicate. Also, because stdout after the 64-MiB capture threshold is discarded without a truncation flag, a very verbose run can make the “final line” and A48 counts describe only a prefix; this is a source-derived risk, not an observed round-48 event.
- **Other uncapped launches.** The predicate's named r48 allowances are nested selftests and SP1049 `bash -c` (plan 45-49); the counter additionally hard-whitelists direct `/usr/bin/git` and `/usr/bin/mkfifo` children (F48 47-48, 273-284). If the plan's allowance list is exhaustive, those two fixture-tool exemptions are an unlisted counter allowance. The shell allowance does not inspect the `-c` command. The counter judges the four named site signatures independently, but it does not certify every descendant or every unlisted non-site launch.
- **Filesystem view.** Neither F48 nor A48 checks bwrap bind mounts or the child's filesystem view. The A48 plan explicitly records that dropping only SP491 `cacheRoot`/SP519 `stateRoot` binds still read held=4/4 and assigns that limit to integration source review plus H1, not to ROUTED_HELD (`plan.md:133`). A passing counter result is not proof that declared binds are present.
- **Base/output validation boundary.** The base's own direct-child/cap-chain state is not re-proved as unheld, and base run fail-line/A48 counts are not part of base validity. Target `status != 0`, execveat success, and other ordinary predicate failures yield exit 1; they are not automatically exit 2. The “trace parses completely” phrase therefore concerns the parser's supported record grammar, not every output byte or gate assertion.

## Inputs that reach exit 2

Code-derived and/or observed `die()` paths (F48 line anchors; A48 retains them except for shifted line numbers):

1. Missing/extra CLI args, unknown `--set`, invalid lane/revision, failed `rev-parse`, failed archive or tar extraction.
2. No strace log, log larger than 1 GiB, or a parsed log with no successful execve/root PID. A real harness incident reached this path when a parent 8-MiB `RLIMIT_FSIZE` made the counter's `prlimit --fsize=4294967296` fail: no log, `CAPROUTE48: ERROR no strace log …`, exit 2 (`build/CtlRetParse48.md:157-160`). This is an instrumentation failure, not a scored miss.
3. Any nonempty unprefixed physical log line; a recognized traced call with an unsupported return suffix; duplicate unfinished call; resumed tracked call without a same-PID/same-name pending entry; pending tracked record at EOF; duplicate created PID; successful execve record lacking a quoted pathname. Synthetic parser cases for `= ?`, unmatched/pending records, and PID reuse are documented in `build/ReviewCounter48.md:163-167`.
4. Any invalid **base** run: nonzero gate status, absent/invalid summary, pass != total, missing final verdict, or zero matching site children (`F48 347-352`). A target timeout/nonzero status by itself instead becomes `gate_exit=<status>` and exit 1 if its log parses; if killing the run leaves a pending/unparseable traced syscall, that parse failure makes it exit 2.
5. Thread-leader `execve` in the traced tree is a concrete strace 7.2 case: `<pid changed…>` has no return, causing `unparsed return in execve` and exit 2. The actual output and parser result are preserved in `r48/ReviewCounterD1.md:14-35`.

There are also uncaught filesystem/runtime exceptions (for example a failing `readFileSync`, `mkdirSync`, or `randomBytes`) that are not routed through `die()` and therefore are not guaranteed to exit 2. Conversely, `die()` calls `process.exit(2)` from callbacks, which bypasses `measure()`'s `finally`; prior harness incidents left extracted scratch trees until manually cleaned (`build/CtlRetParse48.md:163-169`).
