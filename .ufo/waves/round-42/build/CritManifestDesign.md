## Findings: failure scenario, then the smallest safe correction

1. **HIGH: a `KUMITATE_*`-only scrub leaks `GIT_DIR`, and the selftest then commits into the caller's repository.** `cite-check.mjs:1674-1677` runs `git add -A` and `git commit -qm fixture` in a fixture directory, and git follows an inherited `GIT_DIR`. With `GIT_DIR=<my clone>/.git`, the unmutated control read `75/75 PASS`, so a gate would print CLEAN. Meanwhile the run committed `7ba9b82 fixture` (author `t <t@t>`, 1032 files changed, 163552 deletions) onto my clone's HEAD. A real gate run would repeat this once per mutant (42 times per pass). With `GIT_DIR=/nonexistent` the control fails (74/75, exit 2), which is safe but not operable. **Correction:** build the child environment from an allowlist instead of a denylist: `PATH`, `HOME` and `TMPDIR` pointing into the per-mutant temp dir, `LANG=C.UTF-8`, `TZ=UTC`, and nothing from `GIT_*`, `NODE_OPTIONS`, `UFO_*` or `KUMITATE_*`. Add a gate selftest case that runs a control with `GIT_DIR` set to a sentinel repository and asserts that repository's HEAD is unchanged. (The underlying fixture-commit hazard in cite-check is a separate cite-check defect, outside C1.)
2. **MEDIUM: A1's kill rule counts a runtime error as a kill.** The rule is "parseable summary and (exit != 0 or a FAIL line or `VERDICT: FAIL` or passed < total)". A mutant that throws after printing the summary gets exit 1 with `75/75` (or `26/26`) and `VERDICT: PASS`, and stderr shows a TypeError. A1 calls that KILLED, but Stryker calls it a runtime error. **Correction:** killed = a summary whose total equals the control's, plus at least one of: a FAIL line, passed < total, or `VERDICT: FAIL`. Exit != 0 with an all-pass summary is CRASH. All 41 frozen ids stay killed under this rule, because each one prints at least one FAIL line (measured).
3. **LOW: A1 miscounts.** Under the original plan rule, 7 frozen ids read survived, not 6: cite-check `suite-group-verdict`, `suite-any-fail` and `suite-exit-text`, plus census `V382`, `V385`, `V387` and `M19`. **Correction:** say 7 (40 distinct mutations, because M19 and V387 are the same mutation, as A1 already notes).
4. **MEDIUM: vanishing cases (round-41 F4) and a shrunken control.** A1 marks DRIFT when a mutant's total differs from the control's, but the control can shrink too. With the injection markers inherited, the control reads `73/73` (two SKIP lines) for cite-check and `25/25` for wave-census. Wave-census prints no SKIP line in that case, so a SKIP check cannot see it. With no scrub, 9 of 41 survive (round-41 F7, now confirmed on both gates). A1 also gives DRIFT no exit code, yet the plan's "able to fail" demo depends on exactly that: the R41-3 skip-bypass mutants read `73/73 PASS` against a control of 75 (that is, DRIFT), so "`--rev dfabe92` exits 1" only holds if DRIFT maps to exit 1. **Correction:** give each manifest target a case floor (cite-check ≥ 75, wave-census ≥ 26), and exit 2 when a control falls below it. Map DRIFT to the survivor class (exit 1) and print `cases=p/n control=N` on every MUTANT line.
5. **MEDIUM: literal drift collides with this round's routed edits.** Today all 41 anchors match exactly once (E3). But the plan's extra R41-3 demo ids anchor on `if (process.env[INJECT41] !== undefined) {` at line 2459, the very line the F1/F2 guard fix has to restructure [INFERENCE]. That would turn them into `nomatch` at the measured commit, and the plan says extras count toward CLEAN, so the run would exit 2. Separately, the census anchor `dotdot-guard-dropped` sits on `reportOf` (line 106), which the R41-6 sentinel fixes for realpath confinement and trailer anchoring target. Six anchors are 12 characters or shorter, and the plan does not say which exit wins when a run has both a nomatch and a survivor. **Correction:** freeze the manifest against target bytes taken after the ExecCiteGuard and ExecCensusHarden edits land, and record each target's sha256 at freeze time in the manifest. On nomatch, print the current sha next to the frozen one. Run the demo ids from a separate committed receipt manifest that is not part of the CLEAN set. Make exit 2 win over exit 1.
6. **LOW: the census literals are not all in the committed receipts.** The receipts elide or only describe 6 of the 25 census mutants (`string-agent-check-dropped`, `read-error-rethrown`, `M10`, `F-M20`, `F-M22`, `F-M23`). Five more are "drop" edits whose exact span the receipt leaves open (`M12`, `M13`, `F-M07`, `F-M08`, `F-M11`). My reconstruction reproduces every receipt line (exit code, case count, verdict and failing ids: 25/25 identical), but "same literals" cannot be shown from lane files. **Correction:** commit the 25 literal pairs with that identity receipt, and name the reconstructed ids in the lesson.
7. **MEDIUM: process containment fails under concurrency and with detached grandchildren.** The recursing mutant (`!== undefined` changed to `=== '2'`) reached 25 processes in 7.7 s before my cap killed it; round 41 measured 46 processes and 3.2 GB in 10 s. A 60 s timeout times a parallel fan-out is a host memory risk shared by seven lanes. Killing the process group does not reach a `detached: true` grandchild (demonstrated below), and `detached: true` is exactly round-41 CritInjectionBypass's fix suggestion (b) for R41-3. **Correction:** put each mutant in its own cgroup with `systemd-run --user --scope -p TasksMax=64 -p MemoryMax=1G` (available here, systemd 262) and stop the scope, or use a /proc process-count and memory watchdog. Default to running mutants serially or at most 4 at a time, and count leftovers per cgroup, not per group.
8. **MEDIUM: `--rev` reads the wrong repository or bytes.** With an inherited `GIT_DIR`, `git -C <lane> rev-parse HEAD` returns the other repository's commit, and the archived cite-check hashes to 9e190832… instead of 896f0720…. An option-shaped revision (`--output=<path>`) creates a file even though `git archive` fails with exit 128. A ref name like `master` moves between runs. **Correction:** run git with `GIT_*` scrubbed. Resolve with `rev-parse --verify --end-of-options <rev>^{commit}`, reject revisions that start with `-`, and print the full 40-character sha. Hash the exact buffer that is written into the temp copy.
